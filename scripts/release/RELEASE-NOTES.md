CyberGrid v0.9.0 introduces explicit multi-port peer reuse, per-call operation budgets and structured diagnostics for the Rust SDK, addressing the API request in [issue #1](https://github.com/ywateru/CyberGrid/issues/1).

The Rust SDK is **0.4.0**. Other component versions remain Go SDK/CLI **0.4.0**, JS/TypeScript SDK **0.2.0**, Lab **0.4.0**, Node server **0.2.0**, and RAM-only workspace **0.1.0**. Native Lab test builds link the updated Rust SDK. Download matched archives from this project release; existing releases remain immutable.

- Connect once with `Client::connect_with_options()`, then use the same authenticated `Arc<Peer>` for multiple `Peer::map()` / `map_with_options()` mappings or `dial_with_options()` streams. Closing a shared mapping releases its own resources; closing the peer waits for all local session tasks to exit. Legacy `Client::map()` keeps its exclusive ownership and listener recovery behavior.
- `ConnectOptions`, `OpenOptions` and `OperationOptions` expose an absolute monotonic deadline, cancellation, per-call sequential/parallel direct selection, path timeouts and a port-open budget. Forced transport is diagnostic-only and does not silently fall back. All preparation stages consume the remaining total budget.
- `PeerStream` supports AsyncRead/AsyncWrite, write half-close, joined close and per-stream state. Snapshot/watch diagnostics expose local correlation IDs, stage, actual transport, elapsed time, fixed reason codes, retryability and pending cleanup without credentials, endpoints or business content. The recent-resource cache is bounded.
- A slow receiving stream fails explicitly with `ReceiveBackpressure` when its bounded queue fills, keeping the shared mux reader and heartbeat responsive. Task-tracked cleanup, ordered FIN handling and final buffered bytes are covered by regression tests. Applications should handle the new `Error::Operation` variant and inspect `error.diagnostic()`; exhaustive matches may need updating.
- Explicit shared peers expire on runtime-generation/coordination invalidation; they do not transparently reconnect or replay business bytes. Hosts reconnect for new requests. Keep existing authorization, identity and mTLS checks.
- Local validation passed **89 Rust tests, zero ignored**, including the real Redis/Node coordinator tests and 11 new session/diagnostic regressions; rustfmt and clippy with warnings denied also passed. The release workflow separately requires source/license checks, repository integration, and macOS/Android builds before publishing.

See [the peer-session contract](https://github.com/ywateru/CyberGrid/blob/v0.9.0/docs/peer-sessions.md) for examples, limits and verification scope. These changes do **not** establish that CyberNote's phone synchronization failure is fixed: application blocking work, processing budgets, request acknowledgement, phone/WAN and long-run acceptance still require application-level validation. No timeout increase or business retry is presented as a verified fix.

`CyberGrid-0.9.0-source.tar.gz` preserves the complete reviewed public repository, locks and relative sample/SDK/server dependencies. The standalone Rust source archive lacks the repository Node/Redis prerequisites. Source/license manifests, provider pins, `release-manifest.json` and `SHA256SUMS` bind assets to the public commit and Actions run. No private adapter, credentials or user data is bundled.

macOS arm64 App/CLI and Android arm64 API28+ APK/CLI are **debug-test artifacts**. macOS is not notarized; Android uses an ephemeral CI signing key and includes ADB controls. Preserve existing authorization and signing ownership when handling an upgrade signature mismatch. Successful builds are not real Logto Cloud, phone-network or 30-minute/8-hour/24-hour acceptance.
