## 源码与配置契约

代码基线为 `45f8840`，与开发方冻结提交 `a08c90a5` 的三个文件逐字节及 SHA256 一致。新增选择器只作用于连接配置；Lua 与 RedisStore 状态方法保持原字节，没有改变 namespace、epoch、会话、注册 fence 或配额语义，没有新增依赖。

- 显式 `tcp`、`upstash-rest`、`vercel-kv` 只读取所选组。集成注入的其他完整或残缺组不参与选择。
- 未设置选择器时必须恰好存在一组完整配置；非空残缺组或多个组拒绝。空的组变量视为未配置，选择器本身为空字符串则无效。
- 未知选择器、所选组缺失或非法，以及所选连接运行失败都不尝试其他连接，也不退回 RAM。
- `KV_URL` 与 `KV_REST_API_READ_ONLY_TOKEN` 不参与接入，不能代替 `KV_REST_API_URL` 与完整权限的 `KV_REST_API_TOKEN`。
- URL 解析失败仅产生固定错误，不保留原始 input 或 cause；REST token 拒绝空白、控制字符及非 ASCII，避免底层 HTTP Headers 异常携带原值。

早期评审指出 URL 构造异常可能携带原始配置输入，冻结版本已修复。开发方五项专项配置测试与构建通过，未重复旧 Redis 全套。独立补充四项实际配置反例通过：非法 TCP URL 错误脱敏、非法 Unicode token 错误脱敏、显式 KV 不读取其他组与不支持的别名、所选 REST 失败仅发送一次 EVAL 后返回固定 503。后者使用 fetch 夹具，不冒称真实托管请求。

## 真实托管接入证据

核阅实际托管执行的脚本、冻结源与日志，共六项通过：两个 `vercel-kv` Store 与同库 TCP Store 共享 epoch；KV 注册由另一 KV 与 TCP 可见；KV 发布由 TCP 发现；TCP 撤销后两个 KV 均立即拒绝该会话；撤销不改变 namespace epoch。测试使用独立随机 namespace、合成身份，结束后逐个清理并确认无残留键，未使用用户 token 或修改生产／预览 namespace。

初次证据使用此前托管资源；用户随后授权的新自有测试库也完成同样六项实际检查与清理。新库测试脚本的 TCP 连接由该新库配置生成，并非生产环境保留但被选择器忽略的旧 TCP 连接。两次均为开发执行、独立核验脚本与实际输出的托管证据，未记为独立重复运行。原有跨实例原子性验收继续引用 Redis 评审，未重跑旧测试。

## 文档与部署边界

根据 [Vercel 官方 Redis 文档](https://vercel.com/docs/redis)，旧独立 Vercel KV 已停止提供，既有实例于 2024 年 12 月迁移到 Upstash Redis；新项目通过 Marketplace 接入。因此 `vercel-kv` 是 KV 环境变量的兼容选择方式，底层仍使用 Redis 与原 EVAL 协议，不使用已弃用的 `@vercel/kv` 包。

部署说明与站点入口明确要求 `CYBERGRID_REDIS_TRANSPORT=vercel-kv`、完整 REST token、各环境独立 prefix；部署按钮不会自动创建数据库。已有部署必须继续使用原资源、prefix 与容量配置，并在重新部署后核对 epoch，不可照抄示例值覆盖生产 namespace。默认 Compose 仍使用内部 TCP Redis。

独立在内存解析实际拉取的预览／生产新旧配置，确认两环境显式选择 KV、完整 KV pair 指向同一新自有测试库；原 TCP 配置保留且由选择器忽略。各自 prefix 原值不变且彼此隔离，Logto 配置、resource、admin key 与生产 origin 保留。结果只记录布尔值。新增及修改的 14 个公开源文件针对 9 个实际私密值扫描，命中 0；发布方最终公开源扫描也包含新账户管理 API key、数据库密码及 full/read-only token，命中 0。未输出私密值或其哈希。三个部署按钮的参数、两个 HTML 页面的 ID／复制目标及 source-policy 的明确任务／评审路径通过静态核对。
