# Redis 协调存储契约

CyberGrid 的生产协调状态由 Redis 保存。普通 Node.js / Docker 和 Vercel Functions 使用同一服务逻辑、同一认证边界和同一存储契约；实例之间不靠进程内存交换状态。Logto 管理用户、应用与授权，Redis 只保存协调元数据，不保存或转发端到端业务内容。

```text
客户端 ── HTTPS ── Node.js / Docker 或 Vercel Functions
                            ├── Logto：身份、应用目录
                            └── Redis：会话、设备、端口、信令、版本与配额
客户端 ══ WebRTC / iroh / Quick Tunnel ══ 客户端
```

## 连接与生命周期

- 配置标准 `REDIS_URL`，或成对配置 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`，两种方式互斥。缺少或混合配置拒绝启动，不退回 RAM。
- 生产、预览与测试使用独立 namespace；所有关联键使用一致的 Redis Cluster hash slot。关闭客户端只释放连接，不删除共享数据。
- epoch 与注册回执所需的派生密钥在 Redis 中原子初始化，由所有实例共享。Node 重启或 Function 冷启动不改变 epoch。存储重置才创建新 epoch，实例不能无限缓存旧 epoch。
- `Store` 的状态读取和写入全部异步。生产代码不得以本地 `current()`、revision 或计数器作为提交依据。
- Functions 不依赖响应后的定时器、单进程租约或后台清理才能保证正确性。普通 Node 可使用相同逻辑运行多个实例。

## 原子边界

每个实体独立保存并配套有界索引；禁止把全局 RAM 序列化成单个 JSON 值。注册、快照发布、撤销、信令及容量变更通过 Redis 原子操作完成，在提交处重新检查会话、epoch、incarnation、注册 revision 和过期状态。REST pipeline 不具备事务语义，不能替代 Lua 原子校验。

会话 bearer 只以 hash 保存。注册幂等回执由共享密钥派生；结果未知的请求复用原幂等标识。注册 fence 在 namespace 生命周期内保留，受全局与用户容量限制，达到上限明确拒绝新注册键，不静默驱逐。旧 registration revision 不能因清理幂等记录而重新有效；重置整个 namespace 是明确的协调重置，不是自动清理手段。

设备发布维持完整快照语义，revision 单调递增，相同 revision 只接受相同内容；信令检查同用户、同应用、有效设备代际及去重标识。全局信令 cursor / 协调 revision 来自 Redis，不能采用本机时钟或本地递增值。敏感读取与写入使用权威主节点的一致视图，不能依赖可能滞后的只读副本。

所有操作使用普通写路由 `EVAL`，包括鉴权读取，避免只读副本路径；不使用 `EVAL_RO`。这保证的是当前 Redis 执行节点内的原子校验。Upstash 的复制与故障收敛采用其提供商一致性模型，不能把这一实现表述为网络分区或故障切换时的线性一致承诺。

## 到期与容量

Redis 时间作为租约和到期判断依据。会话有效期为 24 小时，设备在线租约为 65 秒，客户端心跳间隔为 20 秒，信令保留 120 秒。设备历史可见性与注册 fence 的保留分别处理，不能将离线设备自动视为未注册身份。

到期记录、索引与容量计数在同一原子边界内懒清理；无需定时 sweep 保证配额正确。所有限制跨实例执行，包含会话、设备、注册键、信令、限流桶与等待者。单设备发布上限 24 KiB，目录响应上限 2 MiB；拒绝超限不能部分修改已发布状态。

长轮询最长 15 秒，使用共享、有到期时间的 waiter lease 和有界轮询。释放 waiter 时校验 token，防止旧请求删除后来持有者。客户端取消、租约到期及实例终止不能永久占用容量。REST 不使用阻塞 Redis 命令；轮询频率应控制成本，免费 Redis 配额不是持续运行的承诺。

Redis 连接失败、额度耗尽或结果无法确认时返回稳定的服务不可用错误，不返回提供商原始响应、凭据或内部地址，不创建第二份 RAM 权威状态。重试只在操作幂等性明确时进行。

## 数据与验收边界

管理后台只返回白名单投影，不展示会话 bearer、信令内容、证书、候选 IP、端点公钥或隧道 URL。Redis 连接密钥、Logto M2M 与管理密钥只通过服务端环境变量提供。

交付验证必须使用真实 Redis 和两个独立 Store / handler，覆盖跨实例发现与信令、注册与发布竞争、撤销后写入、全局容量、TTL、长轮询取消，以及进程重启后会话仍可用。线上验收要确认实际执行 Vercel Functions 并访问 Redis，不能用指向旧服务器的 rewrite 代替。
