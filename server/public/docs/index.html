用 Tauri Lab 完成双端测试

  1. Mac 使用 SDK 随附并校验的固定 provider，无需另外安装；默认不搜索 PATH。Android 使用 SDK 资源生成的 jniLibs，安装后由 nativeLibraryDir 启动，同一 APK 只保留一份原生 provider。
  2. 两端填写同一个真实 Logto Native Application ID，不同本机名称。中央服务默认为 https://cybergrid.aixgg.com，新版本使用 memory-v1 协调协议。
  3. Mac 通过 GUI 发起登录；Android 用下方私有 ADB 工具发起。新版 Lab 会通过官方 SDK 打开系统浏览器完成 Logto 登录；不要复制授权文件。已有本机 v4 授权可显式恢复本机登录。
  4. Mac 在真实设备列表选择对端；Android 用 refresh / connect 命令连接消息端口。发送成功以对端 ack 为准；对端收发区应显示实际消息。
  5. 分别在两个方向执行 64 KiB 校验，核对字节数、SHA256 与实际 transport。Rust / Lab 默认按 WebRTC → iroh 直连 → Cloudflare 匿名隧道尝试，可在高级设置或 ADB 参数选择并行直连策略；强制回退会跳过两个直连阶段，仅作测试参数。
  6. 关闭窗口会关闭短会话和本机 provider、保留本机持久授权；退出登录先停止本次服务，再撤销本端 grant。撤销失败保留材料并提示。

使用真实 Logto 应用与独立授权

应用 ID 严格等于大小写敏感的 Logto Native OAuth client_id；应用须关闭 Device Flow，并有 API resource 的 connect 用户权限。应用只在 Logto 管理。设备控制台只读列出同租户可用应用并可复制 ID，这不是用户已授权应用清单。

新版 Lab 在 Android 使用官方 Logto Android SDK，macOS 前端使用官方 JavaScript SDK，通过授权码与 PKCE 在系统浏览器完成注册 / 登录；SDK 与 App 不收密码、PAT、M2M 或 client secret。登录完成后将最新 grant 一次性交接给 Rust 私有所有者，由 Rust 负责后续恢复、刷新与撤销。后续中央接口使用短期会话；OAuth refresh 保存在各自设备的私有所有者中。

明确指定公开 Native ID
# 从 Logto 或设备控制台复制真实 Native Application ID
read -r CYBERGRID_APP_ID
export CYBERGRID_APP_ID

嵌入主要 Rust SDK

Rust SDK 默认启用 iroh 直连，位于 WebRTC 之后、Cloudflare 匿名隧道之前。可通过 iroh_enabled 关闭此阶段，通过 iroh_timeout 限定单次尝试；direct_strategy 可选默认的 Sequential 或 Parallel 直连竞速，relay 始终禁用。仅同账号、同应用的设备会取得候选地址，控制台及管理后台不显示 iroh 地址。Release v0.7.0 的源码包包含这些配置与连接路径。

解压源码包后，crate 根目录为 cybergrid-sdk-rust-0.2.0；Cargo.toml 位于该目录。若 my-app 与该目录同级，在 my-app/Cargo.toml 添加：

应用 Cargo.toml
[dependencies]
cybergrid-sdk = { path = "../cybergrid-sdk-rust-0.2.0" }
tokio = { version = "1", features = ["full"] }

path 相对当前应用的 Cargo.toml 解析。仓库中的 apps/tauri-test/src-tauri 使用 ../../../sdk-rust；下载完整 Lab 源码则保留包内 apps / sdk-rust / tools 相对目录。SDK 不调用 Go 或 Go FFI。

Rust · 已有私有授权的 CredentialStore 恢复
use cybergrid_sdk::{Client, CloudflaredConfig, Config, CredentialStore, Port};
use std::sync::Arc;

// macOS arm64：使用当前用户 OS cache base，SDK 管理其专用私有子目录。
let cache_base = std::path::PathBuf::from(std::env::var("HOME")?)
    .join("Library/Caches");
let client = Client::new(Config {
    app_id: std::env::var("CYBERGRID_APP_ID")?,
    cloudflared: Some(CloudflaredConfig::bundled(cache_base)?),
    ..Config::default()
})?;
// 真实宿主选择 app-private 目录；不要放在网页目录或日志中。
let store = CredentialStore::new("/absolute/private/device-v4.json");
client.use_credential_store(store.clone()).await?;
client.set_auth_provider(Arc::new(store.clone())).await;
// 首次登录由宿主官方 Logto SDK 完成，并通过 import_browser_grant 安全交接。
// 具体平台与 checkpoint / 所有权确认实现见当前 Lab 0.3 源码。
// 以下仅恢复这台设备已有的私有授权；不存在时应显示网页登录入口。
let tokens = store.refresh(&client).await?;
let session = client.login_with_access_token(&tokens.access_token, "my-device").await?;
client.expose(Port::tcp("sync", 6789, "my-sync-protocol")).await?;
let devices = client.devices().await?;
// 选择已公布 sync 端口的真实远端设备。
if let Some(remote) = devices.iter().find(|d| d.id != session.device_id && d.online) {
    let mapping = client.map(&remote.id, "sync", "127.0.0.1:0".parse()?).await?;
    println!("{}", mapping.addr);
    // 通过本地地址访问，使用完毕 mapping.close().await。
}
// 退出短会话 client.close().await?；退出授权另执行 store.logout(&client).await?。

此为 macOS arm64 的 async 函数内片段，使用已冻结的 bundled 构造；完整错误处理以源码 README 为准。Config.cloudflared 为 None 时不启动本地 provider，仍可连接远端已发布的隧道；new(path) 仅用于显式可信 external override。绑定私有 store 必须在首次 mint 前完成。取消停止后续轮询；一旦 token / refresh 请求已发出，不能 drop 整个 future，必须接管最新 grant 并完成保存或撤销。

JS / TS 只读 SDK 0.1.0

浏览器宿主使用官方 Logto JS / React SDK 完成登录，再把 getAccessToken 回调交给 CyberGridClient。CyberGrid SDK 只在内存保存只读 console 会话，查询应用、同账号设备以及端口明确申报的 port.tunnelUrl；它不注册设备、不发送信令、不代理业务请求。设备离线或未申报端口地址时返回空值，不使用设备内部加密隧道地址替代。

前端须固定可信 issuer、唯一控制台 SPA client ID 与 resource。跨域部署时，服务端配置精确的 CYBERGRID_BROWSER_ORIGINS 列表，并在 Logto 登记宿主回跳。业务端口自身仍须实现授权及所需 CORS。完整 API、构建与取消/恢复规则见 JS SDK 源码说明；Release v0.7.0 提供源码包与包含 ESM、类型声明、README 和许可的浏览器集成包。

Expose 与 Map

Expose 声明本机 loopback 上已运行的 TCP 服务，端口 ID 与类型字符串由应用定义，最多32个。Map 只允许监听本机 loopback，可使用端口0；创建时真实验证远端端口可打开。SDK不会开放远端任意 IP、未发布端口或 UDP。

先用 Devices 核对同账号同应用的远端及已公布端口，选择真实逻辑设备 ID。业务层可以是 API、文件或同步协议；消息业务协议只属于 Lab / 自有应用，不写入 SDK 或中央。

Rust 的 WebRTC、iroh 直连与 Quick Tunnel 三条路径均有端到端 TLS1.3 双向认证和当前设备 fingerprint 校验；Go 保持 WebRTC / Quick Tunnel 两条路径。Rust 默认依序尝试两个直连阶段，也可选择并行竞速，失败后在独立预算内连接 Quick Tunnel；Cloudflare 终止外层 HTTPS，内层业务密钥由设备持有，中央不转发应用字节。

协调失效后重新建立新连接

唯一内存 owner 重启会更换 epoch，丢弃旧协调状态。配置了显式 AuthProvider 的 SDK 单飞恢复注册，保持逻辑设备 ID、重新发布端口和本代证书 / provider URL。短网络故障采用退避，不为每次 poll 刷新 Logto。

原 Map 可以保留本地 listener 和远端逻辑 ID；恢复期间拒绝新连接，Ready 后新的 TCP 重新握手。旧 TCP 会中断，不重放业务字节或旧消息。业务应用应依照消息 ID / ack / 同步协议决定是否重试，不能按设备名把另一个设备当作原对端。

观察 coordination-ready、recovering、requires-login、mapping-disconnected / ready、provider-restarting / failed、closed 事件。Lab 恢复期间清旧连接成功状态并暂停发送，Ready 后只有重新握手和消息 ack 才显示成功。RequiresLogin、用户身份变化或 SESSION_SUPERSEDED 必须停止，不自动抢回会话。

v4 私有凭据与退出

当前 Go0.4 / Rust0.2 / Lab0.3 使用 version4，绑定 server、appId、issuer、clientId、resource、scope 与受信 Device / Token / Revocation endpoints；coordination epoch 是动态状态，不写进固定绑定。旧 v3 / v2 不自动导入、刷新或覆盖，原字节保留；新授权使用独立 v4 文件 / App 私有命名空间。

两端各自授权，不能复制 refresh 文件代替第二端登录。CLI 文件锁覆盖 mint 到 checkpoint；写盘失败时 pending 私有 owner 保留锁 lease，其他进程不能读旧 token 刷新。活进程会保留材料直到保存或撤销完成；provider 签发与本机落盘之间的进程崩溃窗口无法跨系统原子化。

Close 关闭本次短会话和自有资源，不等于撤销 Logto grant。Logout 先停止本端连接再撤销 grant，成功后删除私有文件，失败保留材料。旧 grant 用旧版按原配置或由 Logto 维护者显式撤销；删除文件不等于 provider 撤销。

撤销新的本机 v4 授权
./cybergrid-macos logout -app "$CYBERGRID_APP_ID" \
  -credentials "$HOME/.config/cybergrid/mac-logto-v4.json"

SDK 随附的 Cloudflared

Go SDK 0.4 与 Rust SDK 0.2 随包提供同一组固定 provider 资源，首批支持 macOS arm64 与 Android arm64／API 28+。macOS 使用官方 2026.9.0 darwin-arm64 原始 binary，Android 使用同版本固定 commit 的已记录 DNS 兼容补丁构建。源码包保留来源、archive／binary 校验清单、构建脚本、Apache 2.0 原许可与第三方声明。运行时不下载或自动更新 provider。

macOS：默认内置，不另装

Go 默认 Cloudflared 配置与 Rust 显式 bundled 构造选择内置资源。Go 可用 CacheDir／CLI -provider-cache 指定绝对 cache base；Android CLI 的 -native-library-dir 是显式安装目录，-cloudflared path 为受信 external override，不用于 App 默认接入。SDK 提取到当前用户私有 cache，按固定版本／hash 隔离，在跨进程锁内验证长度、SHA256、所有者与权限后执行。损坏、symlink 或不安全权限明确失败，不自动退回 PATH。只有调用方显式选择受信 external provider 时才使用外部程序；它不享有内置资源的固定字节保证。

Android：通过宿主原生安装目录启动

Go／Rust 随包的 Android 资源与离线脚本供宿主生成 jniLibs/arm64-v8a/libcloudflared.so，配置 native library 提取并禁止 strip。安装后将 ApplicationInfo.nativeLibraryDir 与 App 私有 cache 提供给 SDK 的 NativeLibraryDir／android_native 配置，SDK 只解析并校验固定文件。APK 仅保留一份原生 provider，不再 include 到编译库，也不在可写 files／cache 中解压执行。

每次 spawn 通过受控回调取得当前 LinkProperties DNS，TMPDIR 指向本 App cache；不沿用历史网络地址，不修改系统 DNS、路由、TUN 或代理。缺失安装目录、ABI 不支持、hash 不符或环境回调失败均明确报错，不改用 PATH、可写目录或 ADB shell provider 代替 App 自身启动。

provider 资源、来源与许可证随 GitHub Release 的 SDK 源码包提供，复现资料见 源码目录。新版 SDK／App 不需要另装外部 provider；请使用对应系列清单校验归档。

Rust · Android 宿主构造函数
fn installed_provider(
    native_dir: std::path::PathBuf,
    app_cache: std::path::PathBuf,
    current_environment: cybergrid_sdk::ProviderEnvironment,
) -> cybergrid_sdk::Result<cybergrid_sdk::CloudflaredConfig> {
    let mut provider = cybergrid_sdk::CloudflaredConfig::android_native(
        native_dir, app_cache,
    )?;
    provider.env_provider = Some(current_environment);
    Ok(provider)
}
// 将返回值放入 Config.cloudflared = Some(provider)。
// current_environment 由宿主每次从当前 LinkProperties 生成 DNS 和 TMPDIR。
Go · Android 宿主 provider
func installedProvider(nativeDir, appCache string,
    currentEnvironment func() (map[string]string, error),
) cybergrid.Cloudflared {
    return cybergrid.Cloudflared{
        NativeLibraryDir: nativeDir,
        TempDir: appCache,
        EnvProvider: currentEnvironment,
    }
}

实际测试与平台边界

邮箱验证与找回密码由 Logto 托管；实际邮箱收件链路尚未完成验收，发送成功不代表邮件已经送达。

默认直连优先不等于所有公网网络可打洞。本地 WebRTC / mTLS / smux 互通与 Wi-Fi / 4G 公网观察分开记录；新版已完成实机回退与协调重启恢复验证；公网成功记录仅证实已测网络下的 Cloudflare 回退，不代表公网 WebRTC 直连或所有网络可用。

Quick Tunnel 无 uptime SLA；不提供无损路径切换、UDP 映射、后台长期保活、应用层自动业务重放。中央会话最长24小时，online lease65秒；Logto 浏览器退出或账号禁用不保证即时撤销已交换的中央会话。应用失效由后续目录校验识别。
